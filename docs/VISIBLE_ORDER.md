# Visible-order · 可视区域顺序批量重命名

## 本地启动

只读定位：`.venv/bin/python -m doumao visible-order --preview`

真实保存：双击 `run.command`，等价于 `.venv/bin/python -m doumao visible-order`。

用户在应用中预先打开目标文件夹，不使用搜索/筛选；程序不自动滚动。每批只输入需要修改的数量，不必输入满12个，如 `甲 乙 丙` 只操作位置1、2、3；`3: 甲 乙` 只对应当前可见位置3、4。完成后可以保持同一屏，继续输入 `5: 丙 丁` 操作位置5、6，不需要滚动或凑满12张。名称包含空格可用引号包围。同名作品可以分别处理，输入 `退出` 结束。每批输入后留5秒切回应用，然后按从左至右、从上至下顺序处理。

## 独立可视网格检测（v3）

`core/grid_detector.py` 用灰度图像的边缘和直线结构确定四列三行网格，不依赖浅蓝色背景 RGB 阈值。主要步骤：

1. 在整屏截图上用 Canny 与 HoughLinesP 提取连续垂直/水平边界；合并相邻的平行线。
2. 在候选线中选取五条近似等间距垂直边界和四条近似等间距水平边界；同时检查每条水平线覆盖网格的范围。
3. 从12个单元的内部计算缩略图指纹与局部图像活动度；任意一个预期位置没有可验证图像时拒绝将12格视为已识别。
4. 输出卡片列号、同一行顶部坐标、图像内部点击中心与固定尺寸缩略图。后续由 `core/visible_order_state.py` 按行、列排序与检查。

主要参数为相对截图宽、高的间距、长直线、边界一致性与图像内容阈值；不要求应用窗口始终占满屏幕。程序仍要求应用为前台，避免与其他窗口交互。

完整四列三行优先使用新结构检测器。对不足12张的界面，如结构检测器不能确定完整网格，暂保留旧版 `normalize_titles.card_rows` 作为保守回退。此回退仍依赖原主题的背景像素条件；更换主题或末批剩余作品较少时，应先用 `--preview` 核对标号，不依赖推测位置。两种检测路径均需通过完整行、无跳列及缩略图一致性检查，超出可识别范围则拒绝处理。

## 交互与保存安全性

每批启动时固定当前可见卡片的顺序和位置。写入前读取完整原标题，只覆盖标题，不改标签、备注、分类和图纸。粘贴后回读标题；点击保存并确认编辑弹窗关闭、返回列表后，不再重新打开同一卡片。新标题在保存前已从编辑框回读核对；最终保存后的持久化状态由用户在列表中检查。相同标题仍按不同位置处理；原标题已等于目标则跳过写入并核验该位置。

每次打开下一张前重新截图，检查卡片数、行列位置与本批目标缩略图是否稳定。允许卡片内部的安全点击中心因网格边界检测产生小幅位移，使用最新截图计算的点击点；不允许跨列、明显滚动或缩略图身份变化。保存状态不确定时停止，不自动对同一位置重试。已经确认的完成位置与待人工核对的位置分别记录。
